SPI Send

SPI protocol communication instruction. This instruction sends data or an array to an SPI device and gets a response, which is saved in the provided variable.
SPI protocol supports multiple slaves. To make this function work properly, make sure that the devices support a tri-state configuration when they are disabled.
No more than one device should be on the bus at the same time.
If you need to send several bytes (more than 16bit) to the device you target without changing the chip select signal, put the bytes you have (it doesn't matter how many) in an array and make the communication 8bits. This will allow the spi_send command to send the bytes one by one using only one chip select cycling (high-low- high). This is applicable ONLY when you have a numerical array. But, Text array will be treated differently, and data will be sent byte by byte with chip select cycling per each byte.

Syntax:

spi_send DEVICE_ID, WaitForReply(returned bytes), SPI_DATA (could be an array using a variable), DATASIZE/TYPE =8/12/16, FREQ, SPI_MOD =0/1/2/3 Default=0 , VARIABLE_NAME, DELAY BETWEEN PACKETS(Optional)

-DEVICE_ID: SPI address/Device ID - Decoder from 1 to 15. 0 is reserved for SD-Card
-waitForReply: Do the slave reply back any value?
-SpiData: Data to be sent to the slave. (could be an array using a variable)
-spiDataSize DataSize: Data size or type. DATASIZE/TYPE =8/12/16
-spi_frequency: SPI channel frequency. Typical =1000000
-spi_mode: SPI Mode: SPI_MOD =0/1/2/3 Default=0
-Variable_Name: Variable will be used to save the reply.
-Delay: Delay necessary between packets (Optional)

Example:
MESSAGE="ABCDEFGHIJKLMNOPQRSTUVXYZ"
REM DEVICE_ID, WaitForReply, SPI_DATA, DATASIZE/TYPE =8/12/16, FREQ, SPI_MOD =0/1/2/3 Default=0 , VARIABLE_NAME, DELAY between packets(optional)
spi_send 1,26,MESSAGE,8,5000000,0,myvar,10000;
